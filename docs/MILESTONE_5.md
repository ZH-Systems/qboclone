# Milestone 5: Operational hardening and account recovery

Status: implemented in GitHub feature branch, with PostgreSQL and frontend/API CI gates. Not production-certified.

## Shipped
1. **Server-enforced banking quotas**. New bank rows are metered per tenant and UTC calendar month, in PostgreSQL. Default free allowance is 500 rows/month, Starter 1,000, Business 5,000, Professional 20,000. Duplicate CSV rows do not consume quota; resetting a statement does not refund quota. An over-quota batch rolls back the bank rows and usage increment atomically.
2. **Invitation emails**. Owner/admin can send organization invitations using the API and a configured Resend sending domain. Invites are generated by tenant-checked RPCs, delivered via server-held API credentials, and their secret token is not sent to the browser. The API attempts to revoke an invite when delivery submission fails. A manual private-link fallback remains if the billing API is not configured.
3. **Account recovery**. Supabase Auth password-reset email flow and password update form, with 12-character minimum enforced in the UI. Production Auth policies must be configured separately.
4. **Tenant-scoped data export**. An authenticated owner/admin/accountant may download explicitly allowlisted organization financial and audit data as JSON from the API. The API verifies membership, filters **every query** by the organization id, records an audit event and fails explicitly if any table exceeds 10,000 rows or total content exceeds 20 MiB. Large-tenant archival export remains future work.
5. **Expanded audit coverage**. Append-only audit events for accounts, periods, journals, documents, contacts, payments, bank imports, bank matches, tax codes, membership and subscription changes. Normal roles do not have write grants. A trigger blocks audit UPDATE and DELETE, including privileged application database roles. A DB superuser may disable triggers, so independent DB administration logs are required.
6. **Audit pagination**. Admin/accountant UI retrieves immutable audit events in 50-row pages, indexed by descending event id.
7. **API operational controls**. Security response headers, per-IP rate limits on invitation and export endpoints, structured redacted request logging, liveness and database readiness probes.
8. **Backup tooling and recovery rehearsal**. PostgreSQL logical archive scripts, archive verification, and CI backup and restore into a disposable database. See [Operations Runbook](OPERATIONS_RUNBOOK.md).

## Deploy sequence
Run migrations in filename order, following Milestone 4:
- `supabase/migrations/20261110120000_usage_metering_and_audit.sql`
- `supabase/migrations/20261110130000_expanded_financial_audit.sql`

In the API's secret configuration, add `RESEND_API_KEY` and `INVITATION_EMAIL_FROM` (a verified sender). Retain the existing `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `WEB_APP_ORIGIN`, and `PORT` values. In the frontend set `VITE_BILLING_API_URL` to the deployed API's HTTPS origin.

For local development:
```bash
npm install
npm run verify
npm run api:dev
```
Then, in another terminal, `npm run dev`. Supabase Auth must allow the frontend origin and password-reset redirect URL.

- Verify bank import quota boundary at 500 rows, duplicate replay at zero units, and failed overflow transaction rollback.

- Verify real Supabase Auth password recovery, multi-device login, logout and token expiration.

- Verify export for all tables, empty tenant, deleted contacts, maximum record limits and oversize response.

## Outstanding commercial launch gates
The milestone implements an operational baseline, not certified production security or disaster recovery. Production work still requires:
- Real Supabase integration and a full Auth/Storage backup strategy.
- Stripe test-mode end-to-end subscriptions and webhook replay.
- Deliverability testing with a real Resend domain and outbound email logs.
- Hosted encrypted backups, automated schedule, retention, monitored failure alerts and full restore exercises.
- MFA enforcement, security penetration testing, privacy export for person-level data, and a documented incident-response process.
- Large-ledger streamed archival exports beyond the conservative API limits.
- Tenant quotas for OCR/automatic bank feeds, which are not yet implemented, and complete billing lifecycle policy enforcement.
- Independent accountant validation for the Canadian tax and journal implementation.

The next feature-focused milestone remains advanced accounting, year-end close, refund handling and a validated Canadian tax engine.
